# 汉诺塔游戏 (Tower of Hanoi)

**Status: ready-for-agent**

## Problem Statement

我想用一门新语言(ArkTS)和声明式 UI(ArkUI)做出一个真实能玩的项目来学习它,而不是对着文档敲零散例子。汉诺塔是我选的载体游戏——它有清晰规则、自然的状态管理需求和看得见的动画空间。但问题在于:我过去用 AI 写代码时「测试全绿但行为不对」——这次我想用一套有纪律的流程,让每一步都可验证、都可验收。

## Solution

一个运行在 DevEco Studio 模拟器上的汉诺塔游戏:开局可选 3–8 盘,两步点击移盘(源柱→目标柱),非法移动被拒绝并给反馈,随时显示当前步数与最少步数(2ⁿ−1),全部圆盘移达目标柱时胜利并播放动画。实现刻意覆盖 ArkUI 的标志特性(`@State` 状态托管、`@Builder`/自定义组件拆界面、动画),让游戏同时成为学习载体。游戏逻辑收敛在一个可单测的规则引擎里,UI 只是它的薄包装。

## User Stories

1. 作为玩家,我想要开局时选择盘数(3–8),以便按自己的水平开始游戏
2. 作为玩家,我想要看到三根柱子和按大小顺序堆叠的圆盘,以便一眼读懂局面
3. 作为玩家,我想要两步点击移动圆盘(先点源柱,再点目标柱),以便操作直观
4. 作为玩家,我想要选中的源柱有高亮状态,以便知道自己下一步该点哪里
5. 作为玩家,我想要点击同一根柱时取消选择,以便纠正误操作
6. 作为玩家,我想要执行非法移动时被拒绝并得到反馈,以便学会「大不压小」的规矩
7. 作为玩家,我想要合法移动立即生效、圆盘落到目标柱顶,以便随操作看到局面变化
8. 作为玩家,我想要随时看到当前步数,以便衡量自己的效率
9. 作为玩家,我想要看到当前盘数对应的最少步数,以便知道发挥上限在哪
10. 作为玩家,我想要在全部圆盘按序移达目标柱时触发胜利,以便获得完成感
11. 作为玩家,我想要胜利时播放动画反馈,以便移动与完成都有「手感」
12. 作为玩家,我想要胜利后看到步数对比最少步数,以便评价这局表现
13. 作为玩家,我想要胜利后能重新开局,以便立刻再玩一局
14. 作为学习者,我想要游戏逻辑与 UI 分离且逻辑可单测,以便用测试验证我学到的东西
15. 作为学习者,我想要实现刻意覆盖 `@State`、`@Builder`/自定义组件与动画,以便真正学会 ArkUI 而非只跑通样例

## Implementation Decisions

- **单一模块**:一个游戏规则引擎模块(纯 ArkTS,无 UI 依赖)+ 一个薄 UI 层。引擎持有游戏状态并以公开接口暴露操作;UI 层通过 `@State` 托管引擎实例,渲染与点击只做转发。
- **状态模型**:游戏状态为 `pegs: Disk[][]`(三根柱各一叠圆盘);移动 = 从源柱 pop、push 到目标柱;`Disk` 携带大小标识。该模型直接对应可视结构,合法移动只需比较两叠顶盘。
- **交互流程(两步点击)**:点柱 → 若未选中则选中为源柱并高亮;若已选中:同一柱则取消选择,该柱可移则执行移动并把源柱转移到新柱,不可移则保持局面并给出非法移动反馈。
- **开局盘数**:开局界面提供 3–8 盘选择;新局以当前选择初始化,盘数不在一局中途改变。
- **胜利判定**:目标柱上圆盘数等于开局盘数(全部圆盘按序抵达目标柱)。
- **步数统计**:引擎记录每次成功移动;最少步数由

公式 2ⁿ−1 按当前盘数计算,不依赖历史。
- **动画范围**:胜利动画在 v1 内;具体用 ArkUI 的属性/显式动画 API 实现,选择留待实现期,决策本身是「动画必须出现在 v1,聚焦胜利反馈」。
- **刻意学习清单**(工单拆分依据):`@State` 托管游戏状态、用 `@Builder`/自定义组件拆分柱子与圆盘渲染、至少一处动画——三条 ArkUI 特性必须显式出现在实现中并在复盘时对应到工单。

## Testing Decisions

- **好测试的定义**:只测外部行为——引擎对外可见的输入输出(构造一局、尝试一次移动、查询局面/步数/胜利状态),不测内部实现细节(方法如何编排、私有步骤)。测试必须在「行为坏了」时变红,否则不是真测试。
- **测试范围**:仅规则引擎(唯一接缝)。UI 层是薄转发层,不为其写测试。
- **测试框架**:Hypium——DevEco Studio 内置的单测框架,面向 ArkTS。
- **测试先例**:本仓库暂无任何测试;规则引擎的测试将成为仓库内标准样板,后续实现与测试都以它为对照。

## Out of Scope

- 自动求解演示(最优解动画)——第二版
- 拖拽交互——打磨阶段
- 真机部署与签名配置——模拟器先行
- 音效、皮肤/主题、多语言
- 排行榜/多玩家

## Further Notes

- 学习目标显式高于成品目标:允许为实现「刻意覆盖 ArkUI 特性」拆分学习型工单,每张工单实现后值得一句「学到了什么」的复盘。
- 首次建工程需要人类在 DevEco Studio 点「New Project」(SDK 随向导安装)——这是 agent 无法代替的步骤,后续如重复可固化为 /wizard 向导。
- 本 spec 全程使用对话中确立的术语(圆盘/柱/源柱/目标柱/合法移动/步数/最少步数/胜利);hanoi 仓库的 `CONTEXT.md` 由 domain-modeling 在首次解析术语时惰性创建。
